## Objetivo y límites

Construir una selección mantenible de diez componentes web estilo Shadcn, bajo la dirección visual Base UI3 premium aprobada: tokens claro/oscuro cálidos con grafito y oliva, títulos editoriales serif y UI sans, política de tema acordada, variantes/estados accesibles y primitivas Base UI para menú y diálogos. La entrega debe respaldar AC-001–AC-013 de la spec con tests de componente, navegador y revisión manual cuando corresponda.

No incluye UI nativa Expo, aplicación del estándar en CCentral, API/DB, migración general a Base UI, publicación/release, cambios de CI de despliegue ni catálogo completo de Shadcn. No actualizar Next, React o Tailwind como parte incidental. No introducir paleta final hasta medir y aprobar todos los pares aplicables.

## Stack y base existente

Inspección del checkout actual (confirmar nuevamente al empezar implementación): Next.js `16.3.8`, React/React DOM `19.2.0`, Tailwind CSS `4.1.0`, CVA `0.7.1`, `clsx` `2.1.1`, `tailwind-merge` `3.7.0`, Lucide `1.49.0`, TypeScript `5.7.2`, Vitest `5.0.3`, Playwright `1.63.0`, Prettier `3.4.2`, npm con lockfile. Existe `@radix-ui/react-slot@1.3.3`, se usa en Button `asChild`; `@base-ui/react` no está instalado ni listado en el lockfile. `components.json` declara `new-york`, Tailwind 4, CSS variables y Lucide. Los siete controles sin overlay ya existen bajo `src/components/ui/`, con tokens y clases Slate/teal legacy; sus APIs deben conservar usos compatibles o documentar ruptura justificada. Dialog, AlertDialog y DropdownMenu no existen.

`src/app/globals.css` fuerza `color-scheme: light`, declara colores antiguos, familia Plus Jakarta Sans/Inter y reglas globales. `src/app/layout.tsx` es Server Component, define `<html lang="es">` y `<body>`. El test actual de componentes es principalmente SSR/unidad; los AC interactivos necesitan fixture browser aislado o ruta de test segura y reproducible, sin añadir una página de catálogo pública de producto.

Guías locales de Next 16.3.8 consultadas en `node_modules/next/dist/docs/`: App Router [layout](01-app/03-api-reference/03-file-conventions/layout.md), [font](01-app/03-api-reference/02-components/font.md), [preventing flash before hydration](01-app/02-guides/preventing-flash-before-hydration.md), y [Server and Client Components](01-app/01-getting-started/05-server-and-client-components.md). Implicaciones: mantener el layout raíz como servidor; tema persistido del navegador exige resolver antes del primer paint el tema que no puede saber SSR, con una estrategia inline compatible con CSP/hidratación y prueba de carga directa/navegación cliente; `next/font` auto-hospeda fuentes pero no asumir que una fuente remota se descargará en build. Preferir serif y sans del sistema/locales salvo decisión aprobada que agregue assets/licencia.

## Dependencias y compatibilidad

Dependencia runtime directa nueva indispensable según el alcance: **`@base-ui/react`** (un único paquete; contiene las primitivas Dialog, AlertDialog y Menu que se importan desde subpaths del paquete). No instalar paquetes separados `@base-ui/dialog`, `@base-ui/menu` ni `@base-ui/alert-dialog`. Base UI documenta el paquete único, tree-shakeable y ejemplos de portal. La referencia revisada describe un release publicado `1.8.0`, pero este plan **no fija ni inventa versión**: antes de instalar, `platform_release`/owner de dependencias comprobará release estable actual, peer dependencies, engines, compatibilidad React 19.2/Node 24/npm 11, changelog y APIs oficiales; elegirá versión exacta compatible y registrará evidencia/lockfile. Si no puede verificarse, detenerse y reportar incompatibilidad en vez de usar canary, `latest` flotante o `--force`.

Conservar `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react` y el resto del stack existente. No agregar Motion: CSS respeta `prefers-reduced-motion`. `@radix-ui/react-slot` sólo está respaldado actualmente por Button `asChild`; evaluar su permanencia y compatibilidad durante la migración del wrapper, quitarlo únicamente si ya no quedan imports/usos. No mezclar primitivas de overlays Radix y Base UI. `axe-core`/`@axe-core/playwright` son opcionales en la spec: solo añadir paquete si el owner aprueba e identifica versión compatible; AC automatizables no deben depender de él para empezar. Evitar instalar CLI shadcn si copiar/adaptar wrappers existentes satisface alcance; si se propone, justificar e inspeccionar el diff generado antes de aceptar.

Fuentes oficiales verificadas para Base UI: [Quick start](https://base-ui.com/react/overview/quick-start), [Dialog](https://base-ui.com/react/components/dialog), [Alert Dialog](https://base-ui.com/react/components/alert-dialog), [Menu](https://base-ui.com/react/components/menu) y [releases](https://base-ui.com/react/overview/releases). El quick start documenta el paquete único y portal; verificar durante implementación los props exactos de versión elegida, especialmente outside-click, Escape, modal, foco y API de trigger/render. La aprobación del usuario define política de producto; no asumir que defaults de librería la implementan.

## Arquitectura de implementación

- Tokens semánticos en `src/app/globals.css`, compatibles con Tailwind 4 mediante `@theme inline` o mecanismo actual verificado; aclarar variables CSS sin referencias circulares. Un único atributo/clase de raíz controla claro/oscuro y `color-scheme`; borrar/reemplazar hardcodes legacy solo dentro del alcance y revisar estilos que dependan de clases globales.
- Mantener `src/app/layout.tsx` Server Component. Añadir inicialización del tema antes del paint de preferencia sistema/manual recordada con estrategia documentada (por ejemplo, script pequeño y acotado con política CSP válida). Evitar estado duplicado localStorage/context/document; validar hidratación sin supresión global. Si app ya soporta nonce CSP, reutilizar mecanismo existente; no debilitar CSP.
- Wrapper pequeño cliente para menú y diálogos; hojas públicas con API compuesta estilo Shadcn. Usar Base UI para DropdownMenu, Dialog y AlertDialog. Anclar API final a documentación de la versión instalada. Portal, overlay, foco inicial/retorno, scroll lock, Escape/outside y touch deben ser explícitos. Para Dialog implementar Escape/clic fuera. Para AlertDialog bloquear outside-click; por decisión explícita del usuario del 2026-10-02, Escape equivale a Cancelar: cierra sin ejecutar la acción y devuelve el foco.
- Buttons/inputs/cards/badges/skeletons consumen únicamente tokens; retirar variantes legacy de Badge que chocan con la selección acordada (`teal`, `slate`, `danger`, `neutral`) o conservar compatibilidad temporal mediante mapping deprecado si usos encontrados lo requieren. Buscar todos los callers primero.
- `Button asChild`: evaluar seguir con Radix Slot si está limitado a composición no-overlay y pasa pruebas; decisión del usuario por Base UI aplica como primitive para wrappers de overlays, no obliga por sí sola a migrar Slot. Si cambiar API, documentar caller y regresión.
- Typography usa stacks serif/sans locales o sistema por defecto; cargar nuevas fuentes solo con comprobación de derechos, build offline/reproducible y aprobación explícita del diseño. Mantener escala propuesta como tokens y validar en móvil.
- Showcase de pruebas local aislado para catálogo de variantes/estados/temas en 390×844 y 1280×800; no agregar enlace/ruta pública a la navegación de starter. Reusar fixture disponible únicamente si es viable importarlo sin dependencias cruzadas; si no, crear fixture independiente con scripts claros.

## Contraste y aprobación de paleta

Los hex de la spec son únicamente puntos de partida. La implementación debe tener hoja/matriz versionada con foreground/background para texto normal, grande, placeholder y disabled; primary/secondary/outline/destructive/ghost/link; los siete badges; inputs/borders/error; ring/offset en fondos claros, oscuros y componentes superpuestos; surface/card/popover/overlay; hover/pressed/invalid/disabled. Usar ratios numéricos reproducibles y validar colores CSS ya compuestos (incluida opacidad), no valores nominales sin compositing. WCAG: texto normal ≥4.5:1, texto grande ≥3:1 y componentes/estados visuales necesarios ≥3:1 contra adyacencias. No declarar toda línea decorativa bajo 1.4.11 sin analizar si identifica control/estado. Disabled: no asumir que excepción normativa permite baja legibilidad si se espera lectura; registrar interpretación y mantener etiquetas legibles. Prueba manual perceptual complementa ratios. Si un token falla, reajustar primero semántica por pareja, no introducir overrides ad-hoc por componente.

## Riesgos y cierre

- **Tema/hidratación/CSP:** inline prepaint script tiene riesgo de flash, CSP nonce y mismatch; seguir guía local de Next y comprobar response headers/build. No desactivar CSP ni usar suppressHydrationWarning global.
- **Compatibilidad primitive:** el paquete existe pero no está en este lockfile; verificar version/peers/imports del release estable que se elija; fuera-click y Escape pueden diferir del contrato. Prueba real de teclado/AT, no basarse en snapshots DOM.
- **API heredada:** callers pueden usar variantes Badge que se retiran o `Button asChild`. Buscar usos y asegurar migración compat sin cambios colaterales.
- **Contraste/opacidad:** estados con transparencia pueden romper AA y el borde oscuro candidate tiene margen pequeño; validar composición y cambiar tokens si hace falta.
- **Fuentes:** no usar `next/font/google` con dependencia inadvertida de acceso de build; verificar assets/licencia/fallback si no usar stack de sistema.
- **Fixture:** respetar límites Next 16/Tailwind 4; suite aislada no debe incluir fixture en build ni introducir ruta de demostración pública. Reutilizar fixture previo solo si el acoplamiento queda claro.
- **Checkout sucio:** separar solo cambios de esta feature mediante rama/worktree intencional y archivos listados; conservar trabajo preexistente sin reset/restore/stash.

Condición de cierre: AC-001–013 con evidencia real, pares contraste pass y resultado de revisión, theme policy probado contra flashes/hydration, APIs y dependencias fijadas con lock verificado, visual aprobado, axe/keyboard/AT sin bloqueos, checks aplicables verdes, resultados en `artifacts/results/FEAT-002/`, QA independiente y diff solo de alcance. `COMPLETED` no implica `RELEASED`; CCentral se evalúa en piloto separado tras este gate.
