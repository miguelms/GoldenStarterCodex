# Change log para stakeholders — opcional

El video presenta actualizar un changelog después de cada merge como ejemplo cuando hay stakeholders que necesitan seguir el progreso. No establece que todo proyecto deba mantener uno. GoldenStarterCodex no tiene actualmente un changelog SDD; para cambios del starter, GitHub PRs, releases y commits deben seguir siendo las fuentes técnicas primarias.

**Estado:** `OPTIONAL / NOT ADOPTED` hasta que el owner solicite una vista narrativa de progreso.

Si el proyecto lo requiere, registrar por merge:

- Fecha, PR/commit y feature ID.
- Resultado comprensible para stakeholders y usuario afectado.
- Estado de verificación y limitaciones relevantes.
- Estado de release/despliegue separado del merge.
- Enlaces a spec, PR y release; no copiar diff ni detalles sensibles.

## Entrada plantilla

```markdown
### YYYY-MM-DD — <resultado para usuarios>

- Feature/spec: <ID y enlace>
- PR/merge: <enlace/commit>
- Verificación: <resumen y evidencia>
- Release/deploy: <pendiente/no aplica/completado y referencia>
```
